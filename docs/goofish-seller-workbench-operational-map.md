# 闲鱼卖家工作台操作图谱

日期：2026-06-22  
用途：把 `seller.goofish.com` 工作台按“菜单入口 -> 页面族 -> 可读结构 -> 接口能力 -> 停止点”重新整理，方便后续巡检或自动化先判断能不能进、能读什么、哪里必须停。  
边界：只记录菜单、hash、字段类别、接口家族和风险；不记录真实账号、订单、地址、聊天、商品标题、金额、经营数据、图片链接、二维码内容或登录材料。

## 工作台入口判断

| 入口状态 | 典型信号 | 含义 | 处理 |
| --- | --- | --- | --- |
| 已进工作台 | 左侧菜单、顶部消息/通知、hash 路由出现 | 当前 Profile 具备某个卖家身份 | 只读菜单和页面结构 |
| 站点选择 | `#/select-site` | 账号下可能有多个站点/身份 | 不自动切换站点 |
| 账号检查 | `#/account-check`、`#/account-check?userNick=...` | 需要确认账号/身份上下文 | 不拼账号名，不点继续 |
| 工作台登录 | `#/login` | 需要扫码或验证码 | 用户本人处理 |
| 无权限 | `#/no-permission` | 当前账号无该页面权限 | 记录权限失败，不绕过 |
| 容器页 | `#/iframe?url=...` | 外部页面承接 | 先识别来源，再另行判断 |
| 下载入口 | `#/download`、`#/im-desktop` | 客户端下载/打开 | 不自动下载或安装 |

## 菜单来源和可靠性

- 工作台菜单由外壳和权限接口共同决定，静态包里能看到菜单能力，不等于当前账号一定可见。
- 静态线索包括 `sys.menu.query`、`query.login.merchant.info`、`user.business.identity.get`、`idle.user.account.sub.nav`。
- 当前页面清单中卖家工作台共有 35 个条目，其中 22 个经营/交易页面、5 个门禁页、4 个外壳容器页、2 个消息页、2 个内部模块/测试页。
- 自动化应先读当前可见菜单，再用 hash 路由核对；不能只靠静态 hash 强行进入。

## 工作台巡检顺序

1. 打开工作台首页或目标 hash。
2. 先判断是否落在 `#/login`、`#/select-site`、`#/account-check`、`#/no-permission`。
3. 若进入经营页，先确认左侧菜单组和当前 hash 是否一致。
4. 等待标题、tab、表头、指标卡、输入区、空态或失败态之一出现。
5. 只读字段名、tab、表头、按钮名和状态类别。
6. 遇到导出、下载、保存、发布、发货、退款、评价、投诉、申诉、投放、权限、发送、转接时停止。

## 可记录和不可记录

| 类型 | 可以记录 | 不记录 |
| --- | --- | --- |
| 菜单/路由 | 菜单组、hash、页面族、父子关系 | 当前账号真实身份 |
| 表格 | 表头、筛选项、状态类别、分页结构 | 真实行值、商品名、订单号、地址、金额 |
| 数据图表 | 指标名称、图表类型、日期控件 | 真实经营数字、粉丝画像数字 |
| 财务/发票 | 字段名、tab、按钮名 | 主体资料、税号、银行账号、发票金额 |
| 消息 | 会话框架、输入区、工具栏 | 具体私聊内容、联系人身份 |
| 权限/安全 | 权限字段名、违规字段名、状态类别 | 账号名、手机号、处罚细节、申诉材料 |

## 自动化准入

| 动作 | 默认等级 | 规则 |
| --- | --- | --- |
| 打开 hash、切换左侧菜单 | G1 | 只在当前 Profile 已登录且页面可见时执行 |
| 搜索/筛选/切 tab | G1/G2 | 不输入真实订单、客户、账号或地址关键词 |
| 翻页 | G1 | 只读结构，摘要脱敏 |
| 填草稿 | G2 | 仅限发布、模板、客服回复、申诉材料草稿 |
| 导出/下载 | G3 | 可能导出经营、财务或客服数据，必须确认 |
| 保存/启停/新建/删除 | G3/G4 | 会改变店铺配置或商品状态，必须确认 |
| 发货/退款/评价/投诉/申诉/投放 | G4 | 不主动触发 |
| 登录/切站点/切账号/认证 | G4 | 用户本人处理 |

结论：卖家工作台不是“能打开就能操作”的后台。它的安全策略应先过门禁，再识别菜单组，再只读页面结构；所有交易、财务、导出、权限、客服、消息和投放动作都必须停下确认。
