# 闲鱼导航流转与页面定位指南

日期：2026-06-22  
用途：把“从哪里进入页面、页面加载好了看什么、优先用什么锚点定位”集中整理，供后续只读巡检或自动化脚本使用。  
边界：只记录页面结构、路由、控件和等待策略；不记录真实账号、订单、商品、地址、聊天、金额或经营数据。

总索引：`goofish-master-index.md`，用于从当前所有页面理解文档中选择查阅路径。

配套机器可读清单：`goofish-page-manifest.json`，用于把稳定锚点和停止点交给巡检脚本读取。

配套安全探测规程：`goofish-safe-probe-protocol.md`，用于把定位、等待、读取、停顿和输出串成固定执行顺序。

配套机器探测策略：`goofish-probe-policy.json`，用于让脚本按页面族和证据等级套探测规则。

配套站点层级：`goofish-site-taxonomy.md`，用于把导航入口放回主站、卖家工作台和页面家族结构。

配套逐页就绪矩阵：`goofish-page-readiness-matrix.md`，用于页面定位后快速查看证据、层级、锚点和停止点。

配套任务流手册：`goofish-task-workflow-runbook.md`，用于把导航步骤放进具体买家/卖家任务路径。

配套控件清单：`goofish-ui-control-inventory.md`，用于页面定位后继续判断稳定控件、误点风险和读取顺序。

配套页面接口对照：`goofish-page-api-crosswalk.md`，用于页面定位后判断背后接口家族和风险边界。

配套静态信号矩阵：`goofish-static-signal-matrix.md`，用于在页面跳转、登录失效、H5 承接或 deep link 出现时判断含义。

配套状态清单：`goofish-page-state-modal-inventory.md`，用于在定位页面后继续判断加载、空态、错误、登录、权限、二维码、确认弹窗和高风险业务状态。

## 总原则

1. 先用 URL/hash 判断页面类型，再用页面标题、tab、按钮和表头做二次确认。
2. 主站商品流是异步瀑布流，搜索和频道页进入后要等待并滚动一次。
3. 卖家工作台是 SPA/hash 路由，左侧菜单可能需要先展开父级，再点子项；已知路由可直接打开 hash。
4. 不靠整页文本做结构判断，页脚 SEO、安装包链接、埋点字符串和静态资源会污染结果。
5. 页面带订单、商品、用户、账号、支付、物流、发票参数时，按更高风险处理。

## 主导航流转

| 起点 | 入口/动作 | 目标页面 | 成功信号 | 停顿点 |
| --- | --- | --- | --- | --- |

## 页面加载信号

| 页面类 | 加载完成信号 | 等待/重试建议 |
| --- | --- | --- |
| 首页 | 搜索框、频道入口、推荐卡结构可见 | 等搜索框先出现，再读商品卡 |
| 搜索页 | 搜索框值、排序栏、价格输入、标签筛选可见 | 等 2-5 秒，滚动一次，再读商品卡 |
| 频道页 | 频道商品流、商品卡链接可见 | 等瀑布流加载，不只看首屏 |
| 商品详情 | 价格区、卖家卡、图片区、聊一聊/立即购买按钮 | 按字段区块判断，不靠标题 alone |
| 个人/收藏/买到的 | 左侧导航、tab、卡片/订单结构 | 登录态过期时先停，不自动登录 |
| 订单/确认订单 | 字段名出现：订单、地址、物流、支付方式等 | 只读字段名，真实值不落日志 |
| 发布页 | 图片、描述、价格、发货设置字段出现 | `发布` 禁用/可用状态都不自动点击 |
| 消息页 | 空态或会话框架、输入区/工具区出现 | 未授权不进入具体会话 |
| 卖家工作台 | 左侧菜单、顶部账号/通知/消息区、目标表头 | 菜单点击失败时直接打开确认过的 hash |
| 财务/数据页 | tab、日期控件、表头、导出按钮 | 导出按钮出现不代表可点击 |

## 稳定锚点优先级

| 优先级 | 锚点类型 | 适用页面 | 说明 |
| --- | --- | --- | --- |
| 1 | URL/path/hash | 全站 | 先判断域名、path、hash 和参数形态 |
| 2 | 页面标题/主标题 | 主站/工作台 | 用标题确认页面类别，但不要依赖真实商品标题 |
| 3 | tab/状态栏 | 搜索、收藏、订单、财务、交易 | tab 比整页文本更稳定 |
| 4 | 表头/字段名 | 卖家后台、订单、账号、发票 | 只记录字段名，不记录真实值 |
| 5 | 按钮名 | 发布、反馈、订单、工作台 | 结合动作门禁判断能否点击 |
| 6 | href 包含路由 | 商品卡、订单详情、频道入口 | 例如 `/item?id=...`、`/order-detail?orderId=...` |
| 7 | 可见弹层标题 | APP、商品码、区域、选择区域 | 弹层出现后再操作，不保存二维码/地址 |

## 不稳定或高噪声来源

| 来源 | 问题 | 处理 |
| --- | --- | --- |
| 页脚 SEO 链接 | 会混入大量站点地图和类目词 | 不用整页文本抽商品 |
| 压缩 JS 字符串 | 会抽到资源、埋点、库函数误伤 | 只保留可信路由/API |
| 搜索 URL | 筛选状态不一定写入 URL | 读可见选中态和控件值 |
| 卖家侧 DOM | 未展开菜单可能在 DOM 中但不可点 | 先展开父组或直接打开 hash |
| target/new tab | 一些入口会新开页面 | 自动化要检查当前页和新页 |
| 二维码/扫码 | 内容敏感且会变 | 只记弹层类型，不保存内容 |
| 地区筛选 | 区域文本和分页数字接近 | 先确认弹层可见再点 |
| 支付/售后/认证页 | 可能进入不可逆或高敏流程 | 只读结构，不推进 |

## 自动化读取顺序

1. 读取当前 URL/hash，归类到主站、卖家工作台、外部容器或未知。
2. 查 `goofish-evidence-coverage.md`，确认是 Live + Static、Static Only、Deep/Param 还是 Boundary Only。
3. 查 `goofish-page-field-inventory.md`，决定哪些字段可记录。
4. 查 `goofish-action-gate-matrix.md`，决定当前按钮/动作能否执行。
5. 只在 G0/G1 且字段不高于 F2 时做自动只读摘要。
6. 遇到 G3/G4 或 F3/F4，停止并让用户确认。

## 失败判断

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| 跳到 `/login` 或登录弹层 | 登录态失效 | 停下，让用户登录 |
| 出现 `#/no-permission` | 权限不足 | 记录权限状态，不重试高风险动作 |
| 页面显示空态 | 可能没有数据或筛选太窄 | 只记录空态和筛选条件，不推断业务结果 |
| 商品流一直加载中 | 瀑布流未完成或网络慢 | 等待、滚动一次；仍失败则记录加载失败 |
| 工作台菜单点不动 | 父级未展开或 DOM 隐藏 | 展开父组或直接打开 hash |
| 进入未知 iframe | 外部来源不明 | 停下确认来源 |
| 出现确认弹窗 | 动作即将提交/保存/发送 | 不点确定，先确认 |

## 输出示例

推荐写法：

- 页面：`/search?q=...`
- 锚点：搜索框、排序栏、商品卡链接
- 状态：商品流已加载
- 风险：收藏/联系/购买前确认

不要写：

- 真实商品标题、商品 ID、卖家昵称、账号名、订单号、地址、聊天内容、金额或 cookie/token。
