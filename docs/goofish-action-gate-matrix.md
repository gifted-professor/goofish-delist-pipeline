# 闲鱼页面动作门禁矩阵

日期：2026-06-22  
来源：当前页面地图、路由索引、接口审计和已登录只读探索。  
用途：把“页面上看到按钮后能不能点”整理成执行准入表。只记录动作类型和字段名，不含账号、订单、地址、聊天、商品标题、金额或经营数据。

总索引：`goofish-master-index.md`，用于从当前所有页面理解文档中选择查阅路径。

配套机器可读清单：`goofish-page-manifest.json`，用于让脚本先按页面停止点筛掉高风险动作。

配套字段清单：`goofish-page-field-inventory.md`，用于判断同一页面里哪些字段可记录、哪些必须脱敏或禁止记录。

配套站点层级：`goofish-site-taxonomy.md`，用于判断动作发生在公开发现、登录买家、交易、卖家经营、身份门禁还是内部容器层。

配套逐页就绪矩阵：`goofish-page-readiness-matrix.md`，用于把页面证据、层级、锚点、任务入口和停止点放在一行里复核。

配套任务流手册：`goofish-task-workflow-runbook.md`，用于把按钮和接口动作放回具体任务路径，判断在哪一步必须停下。

配套控件清单：`goofish-ui-control-inventory.md`，用于判断按钮、输入框、表格操作列、上传下载、二维码和确认弹窗的控件风险。

配套页面接口对照：`goofish-page-api-crosswalk.md`，用于把页面按钮和接口家族对齐，遇到写入/支付/售后/消息/权限接口时按更高风险处理。

配套状态清单：`goofish-page-state-modal-inventory.md`，用于判断页面处于加载、空态、错误、登录、权限、二维码、确认弹窗还是高风险业务状态。

## 门禁等级

| 等级 | 名称 | 含义 | 执行方式 |
| --- | --- | --- | --- |
| G0 | 公开只读 | 不依赖个人数据或不改变账号状态 | 可直接打开、搜索、滚动、截图、读公开字段 |
| G1 | 登录只读 | 需要登录，可能含个人/经营数据，但不改状态 | 可打开和读字段名；摘要必须脱敏 |
| G2 | 草稿辅助 | 可帮写内容或填入输入框，但不提交 | 填草稿前说明目标；提交/发送前停下 |
| G3 | 明确确认 | 会改变账号、商品、交易、消息、财务或权限状态 | 用户逐项确认后才操作 |
| G4 | 禁止主动触发 | 支付、确认收货、退款/赔付/举证、认证、内部测试等高风险动作 | 不主动触发；只说明结构和风险 |

## 接口动作词门禁

这些词如果出现在接口名、按钮名、URL 或弹窗文案里，按更高等级处理：

| 词 | 默认等级 | 例子 |
| --- | --- | --- |
| `query`、`list`、`render`、`detail`、`summary` | G1 | 可以只读，但返回内容需脱敏 |
| `search`、`suggest`、`feed` | G0/G1 | 搜索公开页可直接做；登录页结果脱敏 |
| `preget`、`prepublish.check`、`badwords.prepubcheck` | G2 | 可做发布前检查，不等于可发布 |
| `edit`、`update`、`operate`、`remark` | G3 | 会修改账号/商品/消息状态 |
| `create`、`publish`、`submit`、`apply`、`save` | G3/G4 | 创建或提交真实业务状态 |
| `pay`、`doPay`、`dopay`、`transfer` | G4 | 资金或支付动作 |
| `refund`、`compensate`、`refuse`、`agree` | G4 | 售后、退款、赔付 |
| `consign`、`logistics`、`mailno`、`address.modify` | G4 | 发货、物流、地址变更 |
| `message.send`、`card.send`、`mark.read`、`unread.clean` | G3 | 发送或改变消息状态 |
| `blacklist.add`、`blacklist.remove` | G3 | 改变用户关系 |
| `export`、`excel.url`、`download` | G3 | 导出/下载数据 |
| `proof`、`dispute`、`complain`、`appeal` | G4 | 纠纷、投诉、举证、申诉 |
| `identity`、`verify`、`account`、`usergroup` | G3/G4 | 账号身份、权限、认证 |

## 执行前停顿条件

遇到任一条件，必须先问用户确认：

- 页面带 `orderId`、`itemId`、`userId`、`peerUserId`、账号名、手机号、地址、发票、物流、支付参数。
- 点击后可能出现提交、保存、发送、支付、上传、下载、导出、授权、认证、安装、打开外部链接。
- 页面属于订单、售后、投诉、财务、发票、子账号、安全中心、消息会话、账号检查、登录认证。
- 文案里出现同意、拒绝、确认、撤销、申诉、举报、赔付、发货、改价、下架、删除、拉黑。
- 即使用户已授权某一步，下一步进入新风险等级时也要重新确认。

## 日志和输出规则

允许写入文档或日志：

- 页面路径、hash、页面标题。
- 字段名、按钮名、tab 名、表头名。
- 状态类别和风险等级。
- 是否打开成功、是否需要登录、是否权限不足。

禁止写入文档或日志：

- 昵称、会员名、手机号、证件、支付宝、二维码内容。
- 订单号、物流号、商品 ID、买家/卖家身份。
- 收货/退货/发货地址。
- 商品标题、聊天内容、投诉/评价正文。
- 金额明细、开票金额、收入/支出/退款/赔付具体数值。
- cookie、token、localStorage、sessionStorage、密码、验证码。

## 多账号动作边界

- 多账号切换不是“给密钥切号”，而是选择独立浏览器 Profile。
- 自动化只保存账号别名和 Profile 路径，不保存 cookie、token、密码、验证码。
- 每次执行前只读确认登录态，输出时写账号别名，不写真实会员名。
- 出现扫码、验证码、实人认证、账号选择、账号找回，交给用户本人。
- 同一个任务跨账号执行时，每切换一次 Profile 都重新做门禁判断。
