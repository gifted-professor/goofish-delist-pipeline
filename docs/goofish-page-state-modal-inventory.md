## 状态层级总览

| 状态层 | 典型信号 | 意义 | 自动化处理 |
| --- | --- | --- | --- |
| S0 正常内容 | 页面标题、tab、表头、商品卡、订单卡、输入区出现 | 页面可读 | 只读提取字段结构，按字段清单脱敏 |
| S1 加载中 | loading、Skeleton、Spin、瀑布流占位、站点配置加载 | 页面还没稳定 | 等待目标锚点，不急着判空 |
| S2 空态 | 暂无数据、暂无商品、暂无评价、无推荐、未选择会话 | 当前列表没有内容或没有选中对象 | 记录“空态类型”，不制造数据 |
| S3 网络或接口失败 | 未知错误、网络异常、点击刷新、页面出错、加载地图失败 | 只读请求失败或资源失败 | 可刷新一次；失败后记录，不继续动作 |
| S4 登录态失效 | 登录弹窗、扫码登录、跳转登录页、会话过期错误 | 当前 Profile 未登录或登录失效 | 停下让用户扫码/确认账号，不采集登录材料 |
| S5 权限或身份门禁 | 无权限页、账号检查、站点选择、身份选择 | 当前账号不能直接进入目标页 | 只记录门禁类型；切换站点/账号前确认 |
| S6 APP/二维码承接 | 扫码去 APP、APP 管理地址、扫码举报、扫码付款、实名认证二维码 | PC 端无法完成或平台要求 APP | 默认只说明用途；扫码、绑定、付款、认证前确认 |
| S7 确认弹窗 | 确定/取消、关闭、删除、下架、取消关注、关闭订单 | 二次确认，通常会改变状态 | 不默认点“确定”；先向用户复述后果 |
| S8 表单校验 | 必填、格式错误、库存不足、数量为 0、上传限制 | 草稿或输入不满足规则 | 可帮用户修草稿；提交前仍确认 |
| S9 文件/导出 | 上传中、上传失败、下载文件、导出、历史下载 | 会传输图片、文件或经营数据 | 上传/下载/导出前确认范围和目标 |
| S10 高风险业务态 | 待支付、支付成功、交易关闭、退款中、投诉、发货、赔付 | 交易、售后、资金、履约状态 | 默认只读；提交、支付、同意、拒绝、举证都停 |

## 全局状态信号

### 加载与稳定

- 主站商品流常见 `加载中...`、骨架屏和瀑布流延迟。首页、搜索、频道、推荐模块要等商品卡或空态出现，不能只等 URL。
- 搜索页地区/地图相关状态比较多，包括地理权限拒绝、地图初始化失败、城市编码失败、POI 为空、逆地理编码失败。地区筛选自动化要先确认弹层和选项可见。
- 卖家工作台会先加载站点配置和用户信息，再进入 hash 路由。不要在“站点配置加载中”阶段判断页面不存在。
- 工作台页面出错或页面不见时，信号通常是刷新/重试文案；可刷新一次，仍失败就记录失败状态。

### 空态

- 商品流空态：无推荐、未找到想要的宝贝、没有合适位置信息。
- 个人页空态：暂无商品、暂无评价。
- 收藏页空态：没有推荐或收藏列表为空。
- 订单/表格空态：暂无数据、暂无。
- 商品/下单空态：暂无库存。
- IM 空态：未选择会话或暂无会话。默认只记录框架，不读取具体私聊。

### 登录与权限

- 主站和工作台静态包都出现会话过期、非法访问一类错误码。处理方式是进入登录流程或显示登录弹窗，不应该绕过页面直接请求接口。
- 登录页、找回账号页、选择账号页、登录校验页都属于身份流程。可以识别页面类型，但不自动填账号、不切换账号、不保存登录材料。
- 工作台 `#/no-permission` 是权限失败判断页；`#/select-site` 是站点/身份选择；`#/account-check` 是账号检查。它们都是门禁状态，不是业务页。
- 多账号执行时，一个浏览器 Profile 对应一个账号。每次动作前只读确认“当前账号已登录”，不要把登录态跨 Profile 混用。

### 二维码与 APP 承接

- 主站常见二维码承接：登录、APP 查看、APP 编辑资料、APP 举报、APP 管理/添加地址、扫码付款、实名认证。
- 工作台常见二维码承接：数据页 APP 查看、IM 桌面端下载、部分业务详情或安装入口。
- 二维码只作为“需要用户在 APP/外部端继续”的信号。除非用户明确要求并确认，不替用户扫码、不推进付款、认证、地址修改或安装。

### 确认弹窗

- 二按钮弹窗一律按高一档风险处理，尤其是“确定/取消”“关闭/暂不关闭”“删除/取消”“下架/取消”。
- 弹窗里的“确定”不是安全默认值。即使页面动作看起来简单，也先说明会改变什么状态。
- 如果弹窗来自只读动作误触，优先关闭或取消；关闭前也要确认不会造成状态改变。

### 表单与文件

- 发布、反馈、订单地址、退款/投诉材料、IM 文件、物流 Excel、数据导出都属于输入或文件流转。
- 可以帮用户检查草稿、字段缺失、图片数量和格式限制。
- 上传、提交、保存、发送、导出、下载前必须停下确认目标、内容和数据范围。

| `#/account-check` 账号检查 | 账号检查文案、继续/登录入口 | 账号不匹配或未登录 | 继续、重新登录、切换 | 不自动切号；用户确认后才继续 |
| `#/login` 工作台登录 | 登录中、登录弹窗、扫码 | 登录失败、续登失败 | 扫码登录 | 用户自行登录 |
| `#/no-permission` 无权限 | 无权限文案 | 权限失败 | 无业务弹窗 | 只作为失败状态 |
| `#/iframe` 外部容器 | iframe 地址或加载态 | 加载失败、无权限 | 外部页面动作 | 只识别容器，不跨域执行业务动作 |
| `#/download` 下载入口 | 下载/安装提示 | 下载失败 | 下载按钮 | 下载前确认 |
| `#/playground` 工作台实验 | 测试入口 | 测试失败 | 测试动作 | 不主动触发 |

## 状态处理顺序

1. 先看 URL/hash，确认路由属于主站、工作台、深层参数页还是外壳容器。
2. 等待加载信号消失，或等页面标题、tab、表头、商品卡、订单卡、输入区、空态之一出现。
3. 先排除登录态失效、无权限、站点选择、账号检查这类门禁。
4. 如果是空态，记录空态类别，不通过新增、发布、下单、联系来“造数据”。
5. 如果是网络/接口失败，可刷新一次；仍失败就记录错误，不继续点击有状态动作。
6. 如果出现二维码或 APP 承接，记录承接类型，等待用户自己处理或明确确认。
7. 如果出现确认弹窗，先判断弹窗来源和后果；没有用户确认就关闭或停下。
8. 如果页面含订单、支付、退款、发货、投诉、财务、账号权限、IM 发送，按最高风险规则处理。

## 弹窗识别优先级

| 优先级 | 识别依据 | 处理 |
| --- | --- | --- |
| 1 | 弹窗标题或正文明确写了删除、关闭、下架、退款、支付、发货、投诉、认证、切换账号 | 停下确认 |
| 2 | 按钮含确定、提交、保存、发布、发送、导出、下载、去支付、同意、拒绝 | 停下确认 |
| 3 | 二维码弹层含 APP、扫码、付款、认证、地址、举报、编辑资料 | 说明需要 APP/外部端，等待用户 |
| 4 | 纯错误提示含失败、异常、超时、重试、刷新 | 可只读重试一次 |
| 5 | 纯说明弹层，无状态修改按钮 | 可读取标题和字段名，关闭前确认不会提交 |

## 不应继续的状态

- 页面要求登录、扫码、验证码、认证、切换账号或选择站点。
- 页面提示无权限、账号不匹配、非法访问。
- 页面进入支付、提交订单、确认收货、退款、赔付、投诉、举证、发货、导入物流。
- 页面出现导出、下载、上传、安装、打开本机客户端。
- 页面进入 IM 具体会话、准备发送文本、文件、商品卡或订单卡。
- 页面弹出删除、下架、关闭、停用、改权限、保存规则、投放计划。

## 输出记录模板

只读巡检时建议按下面格式记录，不写真实内容：

```text
页面：<路由或 hash>
证据：Live + Static / Static Only / Shell / Deep
状态：正常内容 / 加载 / 空态 / 登录态失效 / 无权限 / 二维码承接 / 确认弹窗 / 高风险业务态
可读锚点：标题、tab、表头、卡片结构、输入区、空态文案
弹窗：无 / 登录 / APP 扫码 / 确认 / 错误 / 上传下载
下一步：可只读 / 可写草稿 / 需用户确认 / 禁止主动触发
隐私：已脱敏，不记录账号、订单、地址、聊天、金额、商品标题、图片链接
```
