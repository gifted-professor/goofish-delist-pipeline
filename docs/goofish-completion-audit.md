# 闲鱼页面理解完成度审计

日期：2026-06-22  
用途：对“把所有闲鱼页面搞懂，越细越好”做当前证据审计，区分已经证明、部分证明、不能证明和需要外部上下文的范围。  
边界：本审计只记录页面级证据、覆盖类别、缺口原因和下一步；不记录真实账号、店铺、订单、地址、聊天、商品标题、金额、经营数字、图片链接、二维码内容、验证码、cookie、token 或本地存储。

## 审计结论

当前成果可以证明：已经把当前可识别的 66 个闲鱼 PC 页面入口按页面族、路由、入口方式、字段敏感度、控件风险、动作门禁、状态弹窗、页面流转、Live 覆盖和缺口原因建立了系统化理解。

当前成果不能证明：所有隐藏页、灰度页、真实订单详情、真实售后状态、真实聊天会话、真实下单流程、真实发票/财务明细、真实权限差异和平台实验页都已经完整实测。原因是这些页面必须依赖用户明确提供的业务上下文、账号权限、站点状态或平台灰度，不能为了覆盖率主动制造或猜参数。

因此，本目标当前状态是“可安全收尾并进入实用小闭环”，不是“全站全状态完成”。

## 已经足够进入的实用小闭环

1. 多 Profile 只读覆盖对比：用不同浏览器 Profile 复跑 B0-B7，只记录页面状态类别和停止原因。
2. 自发布商品指标读取：从“我发布的”列表进入商品详情页，只读读取“想要/浏览数”字段；默认不记录具体数字，除非用户授权。
3. 卖家工作台字段盘点：只记录菜单、筛选项、表头、按钮类别和空态，不记录经营数字。
4. 页面变更监测：使用变更哨兵判断页面结构变化、权限变化和高风险控件变化。

## 不应继续自动推进的范围

- 真实订单详情、下单确认、支付成功、售后/退款详情、发货、投诉举证、评价、发票申请、财务下载、投放计划、具体私聊、账号找回、验证码、实名认证、切号、站点切换、iframe 外部目标。
- 这些范围只有在用户给出明确 URL、明确业务目的，并确认只读边界后，才能单独进入。
